# AGENTS.md — 《魔法少女的魔女審判》無劇透角色百科

## 1. 專案目標
本專案是《魔法少女ノ魔女裁判》（魔法少女的魔女審判）的繁體中文、無劇透、非官方粉絲角色百科。讀者是尚未通關或剛接觸作品的玩家。以公開的官方角色介紹為基礎，提供簡潔、易搜尋的角色資訊。網站應可在 GitHub Pages 以純靜態檔案部署。

## 2. 內容與劇透規範（最高優先）
- 僅使用官方公開角色頁面、官方公開故事簡介或明確可查證的非劇透資料。主要來源：https://manosaba.com/
- 不揭露案件真相、兇手、審判結果、角色命運、隱藏身分、後期反轉、未公開魔法或其他推理答案。
- 官方資料若標示「？？？」或未公開，網站也顯示「未公開」；不得猜測。
- 官方宣傳資料可能含有不同版本或更新；每次新增資料都要核對目前官方角色頁面。資料衝突時暫不採用並註明待查證。
- 人名以官方日文名稱為準；繁中譯名若未確認，標示為暫譯，並保留日文原名。
- 不得把粉絲推論寫成官方設定；不得憑印象虛構個性、能力、台詞或經歷。
- 只寫簡短原創摘要，不大量複製官方文字。素材需確認使用許可；不確定時使用自製佔位圖或純文字卡片，並標示非官方網站。

## 3. 技術與檔案結構
專案根目錄：
- `AGENTS.md`：本文件，所有 AI 修改前必讀。
- `index.html`：首頁、網站介紹、搜尋與角色列表的語意化 HTML。
- `style.css`：統一視覺與響應式樣式。
- `script.js`：讀取資料、渲染卡片、搜尋與篩選。
- `characters.json`：角色資料的唯一來源，不在 HTML 中重複硬編碼角色。
- `assets/`：有權使用的圖片及替代圖。
- `README.md`：專案說明、資料來源、啟動與部署步驟。

不使用需編譯的框架或後端；不得要求 API 金鑰。使用相對路徑，例如 `./style.css`、`./characters.json`，以支援 GitHub Pages 子路徑。

## 4. 網頁設計規範
- 風格：暗黑哥德、懸疑、簡潔，不使用血腥或驚悚畫面。
- 色彩：背景 `#15121c`、卡片 `#241d2d`、文字 `#f5eff7`、次要文字 `#c9bdd0`、強調色 `#c8a6dc`。
- 桌面使用多欄卡片；手機單欄；所有內容需可鍵盤操作。
- 每張卡片顯示：姓名、日文原名、囚人編號（如官方有公開）、一句話介紹、官方已公開的魔法（否則「未公開」）。
- 提供搜尋框、搜尋無結果提示、讀取失敗提示、角色詳細資料展開／收合。
- 圖片必須有 `alt`；互動按鈕要有清楚標籤與焦點狀態；文字對比需足夠。
- 首頁醒目標示「非官方粉絲網站・無劇透」。

## 5. 角色資料格式
`characters.json` 使用 JSON 陣列，每個角色物件包含：
```json
{
  "id": "sakuraba-emma",
  "name_zh": "櫻羽艾瑪（暫譯）",
  "name_ja": "桜羽エマ",
  "prisoner_number": "658",
  "category": "囚人",
  "summary": "個性開朗、重視他人的少女。",
  "magic": "未公開",
  "image": "",
  "source_url": "https://manosaba.com/"
}
```
規則：
- `id` 唯一、使用小寫英文字母與連字號；不可因調整譯名而改動既有 id。
- `name_zh` 如無可靠正式譯名，附「（暫譯）」；`name_ja` 保留官方名稱。
- `summary` 以 20～60 字的繁體中文原創摘要為原則，不涉及後續劇情。
- `magic` 僅記載官方已公開的內容，否則填「未公開」。
- `image` 為站內相對路徑或空字串，不使用未獲許可的第三方圖片網址。
- `source_url` 記錄核對來源；缺乏可靠來源的角色資料不得發布。
- 不得加入未定義欄位，除非先同步更新本文件與程式。

## 6. AI 新增角色的標準流程
1. 先閱讀 `AGENTS.md`、`characters.json`、`script.js`，確認既有資料格式與功能。
2. 查證官方公開的角色名稱、編號、個性、魔法；檢查是否有劇透。
3. 檢查 `id` 與日文名稱是否重複。
4. 只在 `characters.json` 增加符合規格的新物件，盡量不修改 HTML、CSS、JS。
5. 若角色沒有可用圖片，保留空字串，讓網站顯示預設佔位圖。
6. 測試搜尋、卡片顯示、詳細介紹、手機版與無結果提示。
7. 在修改摘要中說明新增角色、資料來源、測試結果與任何待確認項目。

## 7. AI 修改網站的規則
- 修改前先說明將變更哪些檔案；只修改完成任務所必需的部分。
- 保持原本配色、字型層級、卡片樣式、繁體中文與無劇透原則。
- 不刪除既有角色、不任意改名、不改動既有資料 id。
- 不引入外部依賴或追蹤工具，除非使用者明確同意。
- 使用 `textContent` 或安全 DOM API 插入角色資料，避免直接把不可信文字寫入 `innerHTML`。
- 修改資料格式時，必須同時更新 `AGENTS.md`、`script.js`、`README.md` 並檢查所有角色。
